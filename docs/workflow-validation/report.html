具体执行过程

Case A — 顺序控制

  • 1）创建 design stage 的 isolated workflow，前置 gate 指向 docs/requirements.md。
  • 2）只生成 docs/design.md，不生成 docs/requirements.md。
  • 3）调用 wf next，3/3 得到 blocked，原因是 docs/requirements.md does not exist。
  • 4）补齐 docs/requirements.md 后再次 wf next，进入 implementation。
  • 5）补齐 docs/implementation.md 后最终 wf next，3/3 终态 done。

Case B — 命令 gate

  • 1）分别创建 pass / fail / repair 三个 isolated project。
  • 2）每个场景均包含 implementation.txt、check.py、package.json、docs/review.md。
  • 3）Pass：npm test 退出码 0，首次 wf next 为 active。
  • 4）Fail：npm test 退出码 1，首次 wf next 为 blocked，重试 1 次。
  • 5）Repair：先失败后修复，npm test 变为退出码 0，gate_calls=2，最终 done。

Case C — 逐轮输入

  • 1）记录 3 个真实 work order：需求、设计、实现。
  • 2）逐轮输入分别为 182 / 191 / 205 bytes，总和 578 bytes。
  • 3）静态 skill 在每轮重复完整 prompt，单轮 1823 bytes，总和 5469 bytes。
  • 4）总量对比：578 vs 5469 bytes，约 89.4% 输入缩减。

验证与发布

  • 2）npm test，44/44 通过。
