# Runtime facts are control-plane authored

Conditional routing must remain consistent with the harness’s core boundary: the agent can produce project artifacts and arguments, but the control plane owns stage progression and route selection. The first conditional-transition design therefore does not add a public command for the agent to set runtime variables or facts.

When a non-terminal step has multiple outgoing edge candidates, `wf next` evaluates the step’s normal gates first. Only after those gates pass does the control-plane CLI evaluate a narrow candidate-edge predicate and select one edge. The author-facing form is `when: <condition-variable> == <literal>`, with `default: true` for the fallback edge; the workflow does not declare a separate variables section and the condition does not specify whether the value came from a runtime fact, start input, or environment value. The CLI resolves the logical condition variable through its controlled precedence. The narrow syntax deliberately avoids a general expression language: unsupported comparisons are rejected by workflow validation.

Runtime facts are produced by control-plane execution of deterministic, workflow-package-defined scripts, or by evaluating a supporting condition at transition time. The resulting fact and selected route are control-plane state and audit history. The agent may influence the project files from which a fact is derived, but cannot directly write the fact, runtime state, or a routing variable. A future decision-model evaluator, such as a Jev-style structured classifier, should be integrated as one controlled value producer behind the same logical condition-variable interface; it must not widen the transition syntax into free-form expressions.

This intentionally avoids Aix-style phase-level `when` skip-cascade, parallel fan-out, and generic failure-outcome routing in the first conditional-routing slice. It also avoids a general `wf set` surface that would return route selection to model self-declaration. A runtime fact is a transition-time value; later changes to project evidence do not retroactively rewrite an already-recorded route, although later stages may use their own gates and conditions as usual.
