# State v2 stores task inputs and current facts

Workflow schema v2 adds task-scoped execution values to the authoritative task state. `state.json` version 2 stores the immutable start inputs admitted by `wf start --var` and the current runtime facts generated by control-plane-owned condition producers. Both maps may be empty, and an absent map is invalid rather than ignored.

The task pointer remains deliberately minimal and continues to contain only the active-task identity fields. Inputs and facts do not move into `task.json`, so the pointer does not become a second state authority.

History remains an audit log, not a route-recovery source. It may record fact generation, route selection, backedge counts, and source drift, but `wf next` resolves the latest condition value from authoritative state. This preserves the v1.2 boundary that current state is authoritative and history is not used to reconstruct progression.

Agent-facing responses do not expose either map. The model still receives only the current work order, blocked reason, or terminal result.
